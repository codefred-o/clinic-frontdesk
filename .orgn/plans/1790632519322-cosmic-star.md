# Vouch Public Lagos Inventory Slice Plan

## TL;DR

> **Quick Summary**: The repository has a strong, tested FastAPI/PostgreSQL foundation and seven constrained domain tables, but only health endpoints are runnable. The right next engineering milestone is a narrower, decision-independent public Lagos inventory slice: make listing publication explicit and safe, define availability semantics, and expose read-only asset search/detail. Audit, idempotency, generic transaction abstractions, and authenticated concierge commands are deferred until the first real write workflow consumes them.
>
> **Deliverables**:
> - Explicit reviewed listing state and minimum trust tier fields, with existing assets kept non-public.
> - Clarified inventory visibility and date-availability contracts.
> - Minimal shared `400`/`404` error, request-ID, decimal, and cursor-pagination conventions exercised by the asset endpoints.
> - Public Lagos asset search/detail endpoints with strict asset and vendor visibility predicates.
> - Automated migration, query, API, redaction, pagination, and availability tests at the existing 90% coverage gate.
>
> **Estimated Effort**: Short to Medium
> **Parallel Execution**: YES — 3 waves
> **Critical Path**: Task 1 → Task 2 → Task 5 → Task 6

## Context

### Original Request
Review the current state of the project and identify what is next in line.

### Review Summary

**Current state**:
- The checked-in runtime is a FastAPI modular monolith with configuration, async PostgreSQL lifecycle, request IDs/logging, CORS, and only two operational endpoints (`README.md:11-19`, `src/app/main.py:17-53`, `src/app/api/router.py:5-8`).
- Seven ORM-backed domain tables and an initial Alembic migration model users/KYC, assets/availability, bookings, payments, and handovers (`docs/ARCHITECTURE.md:11-22`).
- Tests and CI are substantial: pytest/pytest-asyncio, PostgreSQL migration checks, Ruff, and a 90% branch-coverage floor (`pyproject.toml:16-49`, `.github/workflows/ci.yml`).
- The API contract explicitly says every marketplace endpoint is still planned (`docs/API_CONTRACT.md:3-14`).
- Git history shows the latest milestone was the production API/database foundation (`307e334`, incorporating `64f6da4`, `dd5560b`, and `6ecb453`); the branch was clean and tracking `origin/base-setuo` when reviewed.

**Direction review**:
- Public inventory is the smallest useful marketplace capability that does not require decisions about authentication, KYC, payments, or funds custody (`docs/API_CONTRACT.md:61-80,188-217`).
- The current asset model cannot safely publish inventory because it lacks review state and minimum-tier fields (`src/app/db/models/asset.py:32-63`; `docs/SCHEMA.md:238-247`).
- Audit and idempotency are important, but implementing them before any authenticated write command would be speculative: the documented consumers are booking/payment/refund/payout and retried admin commands (`docs/API_CONTRACT.md:42-46`; `docs/ARCHITECTURE.md:208-210`).
- Asset versioning is also deferred because the schema plan assigns versioning to bookings, not assets (`docs/SCHEMA.md:238-247`).
- Date search must first clarify the interaction between `Asset.is_available`, positive availability windows, blocked windows, and confirmed/active bookings (`src/app/db/models/asset.py:32-109`; `docs/SCHEMA.md:111-122,200-232`).

### Scope Boundary

**IN**:
- Public, read-only Lagos asset discovery.
- Asset listing review state, review provenance, and minimum trust tier.
- Strict visibility requiring an active listing, non-deleted asset, active/non-deleted vendor, and Lagos city.
- Minimal API conventions directly exercised by these endpoints.
- Tests-first implementation using existing pytest/PostgreSQL patterns.

**OUT**:
- Audit-event and idempotency persistence/services.
- Generic transaction/repository frameworks and asset versioning.
- Authentication/session issuance, vendor/admin writes, and authorization.
- KYC or Paystack adapters/webhooks; booking/payment/handover commands.
- Evidence storage, disputes, ledger, outbox, workers, notifications, frontend, or Abuja activation.
- Any use of “escrow” in product/API naming or exposure of `protection_waiver`.

## Work Objectives

### Core Objective
Deliver the first safe, useful marketplace API capability without making unresolved provider, legal, or identity decisions and without prematurely building controls that have no command consumer.

### Concrete Deliverables
- One incremental Alembic migration adding safe listing-publication fields; never rewrite `0001_initial_schema.py`.
- An explicit documented rule for inventory visibility and date availability.
- Public `GET /api/v1/assets` and `GET /api/v1/assets/{asset_id}` endpoints.
- Minimal error/request-ID/pagination contracts needed by those endpoints.
- Tests for migration safety, visibility, vendor status, redaction, filtering, cursor behavior, and date conflicts.

### Definition of Done
- [ ] `ruff format --check .` passes.
- [ ] `ruff check .` passes.
- [ ] `pytest --cov=app --cov-report=term-missing` passes at or above 90% branch coverage.
- [ ] PostgreSQL upgrade → downgrade → upgrade passes through the new migration.
- [ ] OpenAPI includes health and the two public asset endpoints, with no planned write endpoints registered.
- [ ] Public responses never include serial numbers, vendor identity/contact data, condition/internal review notes, or non-public inventory.

### Must Have
- Existing assets migrate to a non-public state.
- Only active, non-deleted Lagos assets owned by active, non-deleted vendors are public.
- Date filtering uses one explicitly documented rule and inclusive overlap semantics.
- Pending bookings do not reserve inventory; confirmed/active bookings do.
- Public reads use deterministic ordering and opaque cursors.

### Must NOT Have
- Do not select auth, KYC, storage, queue, or payment providers.
- Do not add vendor/admin CRUD or generic status mutation.
- Do not implement speculative audit/idempotency abstractions in this slice.
- Do not edit the applied initial migration or activate Abuja.
